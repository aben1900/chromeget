# 智能摘要：OpenAI、DeepSeek 与 CC-Switch 配置

日期：2026-10-08
状态：功能范围已确认，书面设计待用户审阅；尚未修改产品代码。

## 用户目标

用户要求先开发智能摘要，可填写模型 API 配置，支持 DeepSeek 和 OpenAI；先放无效 SK 示例，用户之后填写真实密钥。追加要求支持本机 CC-Switch 中 yqn Claude 配置下的模型。迁移功能继续暂缓。

沿用已讨论的交互：资料库选择摘录 → 主动生成摘要 → 审阅或编辑 → 保存摘要。完整原文保留，摘要独立存储。不在后台自动发送个人资料。

本功能新增模型调用、凭据配置和摘要持久化，按架构性改动设计。用户已确认智能摘要及配置模型 API 的方向，本文件落实接口差异、配置来源、数据边界和验收，再进入实施计划。

## 现有证据

- 当前版本 1.26.0，library.html 为完整资料库，library.js 已有单条详情和独立整理索引。
- library.cjs 与 PowerShell journal Mutex 共同保证一致读写；网络调用不得在这些锁内等待。
- 资料库索引 annotations 可保存额外整理字段；备份模块保留兼容的未知整理字段。
- 只读检查本机 CC-Switch 数据库确认 providers 表存在，Claude 类配置名称为 yqn Claude。ANTHROPIC_MODEL 为 glm-5.2，Haiku/Sonnet 映射为 qwen3.7-max，Opus 映射为 glm-5.2。存在 ANTHROPIC_AUTH_TOKEN 与 HTTPS ANTHROPIC_BASE_URL；未打印密钥或完整服务地址，未发起模型调用。
- 上述模型名是用户配置中的值，不代表已验证服务商可用性、底层模型身份或调用成功。

## 方案取舍

1. 推荐本地程序负责模型请求与凭据保管，资料库提供配置和摘要入口。浏览器仅提交选中记录及显式操作，复用现有 Native Messaging，不增加网页访问权限。
2. 浏览器直接调用 API 配置较简单，但密钥需要长期驻留扩展、增加服务域权限，不采用。
3. 所有服务强制套用一种协议会减少代码，却不能可靠兼容 OpenAI Responses 和 Claude Messages；采用协议适配器。

## 配置界面

资料库提供明显的“智能摘要设置”入口，支持三种配置来源：

| 来源 | 配置内容 | 请求协议 |
| --- | --- | --- |
| OpenAI | API 基础地址、模型 ID、API Key | Responses |
| DeepSeek | API 基础地址、模型 ID、API Key | Chat Completions |
| CC-Switch / Claude | 选择配置，选择已配置模型或填写模型 ID | Anthropic Messages |

OpenAI 官方基础地址预填 https://api.openai.com/v1；DeepSeek 预填 https://api.deepseek.com。模型 ID 可编辑，不写死账户一定可用的模型。服务商选择决定协议，地址本身不用于猜测协议。

手动配置的密钥输入框使用 `sk-placeholder-replace-me` 作为占位提示；不是有效密钥，不把它当成“配置完成”，不发请求验证此占位值。保存实际密钥后仅显示“已设置”，支持替换和清除。用户不需要在聊天中发送密钥。

“测试连接”主动发送固定、无个人资料的极短请求；明确可能产生少量 API 用量。未配置真实密钥不允许测试，读取配置不触发测试或自动列举远端模型。

## CC-Switch 接入

仅由用户点击“读取 CC-Switch 配置”时只读访问当前 Windows 用户的 .cc-switch/cc-switch.db，使用已随程序分发的 Node SQLite 能力；不安装 SQLite 或 Python。读取 providers 的 Claude 配置及允许的环境字段，不读取请求日志、会话或其他应用的凭据。

- 以稳定 provider ID + app_type 绑定用户明确选中的配置；不跟随 CC-Switch 当前选择自动切换。
- 识别 ANTHROPIC_BASE_URL、ANTHROPIC_AUTH_TOKEN / ANTHROPIC_API_KEY、ANTHROPIC_MODEL、默认 Haiku/Sonnet/Opus 模型字段。模型去重展示，保留角色提示。
- 当前 yqn Claude 默认模型为 glm-5.2，可选 qwen3.7-max；配置未来改变时以读取结果为准。
- 引用现有配置，不把原始密钥复制到浏览器存储或导出文件；每次主动调用在本机读取所选配置。
- AUTH_TOKEN 使用 Bearer 鉴权；API_KEY 使用 x-api-key。均使用 Anthropic Messages 格式与 anthropic-version 请求头，不将 Claude 配置误认为 OpenAI 接口。
- 如果两种鉴权都存在，使用明确选定的鉴权方式，默认 AUTH_TOKEN 优先，并在连接测试中验证；不自动重试另一种以免重复发送。
- 选中配置的地址、鉴权或模型变化时，已有生成预览失效，提示刷新配置后重新确认目标。不得静默把资料改发至另一服务。
- 数据库不存在、忙、结构不兼容或所选项被删除时显示具体配置问题，允许改用手工配置；不改写 CC-Switch 数据库、当前服务或 Claude 设置。

本机仅保存配置，不代表本机推理；界面展示实际服务域名与模型，发送前明确说明正文将发送到该地址。

## 凭据与传输

手动密钥由本地程序使用 Windows 当前用户 DPAPI 加密，单独保存在安装目录的本机配置文件。通过 Native Messaging 提交用户输入后立即清空页面字段；不回显、记录日志或加入异常详情。进程间通过受控标准输入传递解密结果，不使用命令行参数。

凭据只绑定到保存时确认的协议和基础地址。更改地址需清除或重新明确配置密钥，避免把旧服务密钥发送给新服务。正常远程地址只接受 HTTPS；若支持本机 HTTP，只允许 localhost、127.0.0.1、[::1]，不允许普通远程 HTTP。拒绝 URL 用户信息、查询参数、片段及重定向，不关闭 TLS 验证。

浏览器动作只允许精确的扩展 library.html 调用；网页、iframe、内容脚本不能读配置或请求摘要。错误输出按状态分类，不回显 Authorization、密钥、服务器原始错误正文或摘录原文。

配置、凭据及运行状态均不进入 Git、备份和公开安装包；更新/修复保留配置。备份只含用户已经保存的摘要及其来源信息。

## 摘要流程与范围

首版针对当前资料库中有正文的文字摘录（内容、评论、评阅、提示词），一次一条。网页地址记录只有 URL 时不抓取网页、也不伪称已概括网页内容；下载文件先不解析正文。OCR、音视频转写和相似资料关联不在本轮。

1. 在摘录详情点击“智能摘要”。读取整条原文，而不是列表预览或第一段分页。
2. 展示服务商/服务域名、模型、将发送的字符数和摘要长度选项：简短、标准、详细。默认标准。
3. 用户点击“生成摘要”即授权将这条原文与摘要指令发给所选服务。明确提示可能产生 API 费用；不传其他记录、Cookie、本机路径或浏览历史。
4. 摘要生成后显示可编辑文本、模型、生成时间及“保存摘要”“复制摘要”。显示“AI 生成，请核对”。原文不变。
5. 保存只改动该记录的摘要整理字段，保存前重新核对记录存在与正文指纹；期间正文变动或已删除则拒绝写回。
6. 已有摘要可查看、复制、重新生成。重新生成结果先作为草稿，只有点击保存才替换已保存摘要；操作采用摘要版本检查，避免多窗口覆盖。

按中文概括生成，也允许原文术语保留。指令要求只概括原文、不要编造事实，把摘录中的指令视作资料而非系统指令。模型响应按纯文本显示，不执行 HTML、Markdown 脚本或工具调用。

输入上限首版为 24000 个 Unicode 字符且 UTF-8 正文不超过 96 KiB；超限明确提示，不静默截断，不自动分块多次计费。单次输出最大 16000 个字符，生成 token 上限由适配器设置为 4096；具体模型上下文或账户限制不足时显示服务错误。长度选项是生成要求，不保证固定字数。

## 网络、锁与重复请求

读取记录快照、写生成状态和保存摘要时遵守 journal Mutex → library pipe 的顺序。HTTP 请求必须在释放资料锁后执行，以便其他摘录保存与下载快照不被模型响应阻塞。

每次主动生成分配唯一请求 ID，并绑定记录 ID、正文指纹、配置修订号、模型与长度。相同 ID 重试只查询已有状态，不再次自动发起收费请求。状态持久化为准备/处理中/完成/失败或结果未知；正文与明文密钥不写入运行状态。

请求 45 秒超时，限制响应大小；浏览器断连不等于请求未执行。超时、进程中断、429 或 5xx 均不自动重新生成；用户可核对原请求，确认要再调用后创建新请求 ID。并发同条记录生成需防重入，结果绑定原记录，切换详情不得串入其他记录。

状态和摘要草稿只保存在本机，关闭资料库后可找回最近一次生成结果；保存摘要后才纳入资料备份。不得把网络异常展示为成功，也不通过假 SK 生成模拟摘要冒充真实模型结果。

## 摘要数据与备份

资料库索引 annotation 下新增单个 summary 对象：文本、提供方显示名称、模型 ID、生成时间、正文 SHA-256、版本 ID、是否用户编辑。保存记录 ID 不变，不把模型密钥、完整自定义端点或 API 响应调试信息写入摘要。

备份验证补齐 summary 字段类型/长度；恢复沿用单值冲突保留当前的规则，界面能区分 AI 摘要与原文。摘要是可选整理信息，旧资料库无此字段照常工作。现有 Markdown/ZIP 原文导出保持原有内容语义，本轮通过“复制摘要”复用摘要。

## 模块及交付

新增独立 AI 设置/请求/协议适配模块及 library-ai.js，避免继续扩大 library.js。PowerShell 负责 DPAPI 与共享锁桥接，Node 负责只读 CC-Switch、有限网络请求和状态。新增明确 capability，旧宿主给出更新提示。

目标版本 1.27.0，完成后更新功能清单、使用说明、隐私说明、安装复制列表及打包审计；保持唯一“开始使用.cmd”入口。沿用当前开发分支和当前会话顺序实施，最终独立审查；不推送、不发布，不开展迁移功能。

## 验收

1. OpenAI Responses、DeepSeek Chat Completions、Claude Messages 各自请求、鉴权、输出解析均使用本地模拟服务验证；覆盖缺少文本、拒绝回答、截断、超时、错误状态和异常响应大小。
2. 占位 SK 不联网；真实手动密钥加密保存，配置返回和日志不含密钥，修改地址不能复用旧密钥。
3. CC-Switch 使用含假密钥的隔离数据库 fixture 验证 yqn Claude 和模型映射、配置变化、数据库忙/不存在；真实数据库只读检查不更改任何设置。
4. 整条长正文、不同长度、编辑保存、保留原文、备份恢复摘要通过测试；超限明确拒绝。
5. 同条双击、丢响应、详情切换、多窗口保存、期间原文变化、进程中断不造成错误记录写入或自动重复付费。
6. API 请求期间并发摘录保存仍可完成；鉴权、TLS、非可信调用者和重定向边界通过测试。
7. 320/390/600/1440 宽度、键盘与状态提示、全部相关 P0/P1/备份回归通过；临时目录 SkipRegistration 安装保留配置且不泄露密钥。
8. 当前无用户填写的新 API 密钥，不执行收费真实调用。对 CC-Switch 的已有凭据也只做读取验证；首版交付如只完成模拟测试，明确标注真实服务调用待用户主动测试，不能声称已验证三家线上可用。
