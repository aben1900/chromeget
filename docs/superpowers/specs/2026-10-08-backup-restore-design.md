# 本地备份与恢复

日期：2026-10-08
状态：用户已确认设计；实施计划已完成，待审阅；尚未修改产品代码。

## 目标和范围

用户要求继续开发，承接上一轮建议，先实现“本地备份与恢复”，随后再考虑新电脑迁移。帮助个人用户保护已保存的摘录、来源、标签、集合和下载资料索引，恢复时知道哪些内容会增加、哪些冲突会保留。

本轮备份默认摘录数据.json 与资料库索引.json 中的整理信息及下载资料快照，不包含视频、图片、模型等实际下载文件，不包含浏览器 Cookie、引擎、运行日志、扩展 ID 或注册信息。外部 JSON 不自动合并。备份是资料数据备份，不宣传为整机迁移包。

## 现有代码约束

- native/host.ps1 负责摘录保存、删除，采用目录级 Windows Mutex 和原子单文件替换。
- native/library.cjs 负责整理索引，采用目录级 Windows named pipe 互斥和原子替换。
- 两种写入目前各自加锁；恢复同时写两份文件，必须统一写入顺序和恢复事务，不能简单覆盖两次文件。
- extension/library.html 是完整资料管理入口；Native Messaging 返回摘要，备份正文及文件内容不经过浏览器消息传输。
- 现有导出用于分享，备份文件必须独立命名和格式校验，不能将任意 JSON 或导出 manifest 当作可恢复备份。

## 方案选择

采用单个带版本和内容校验的本地备份文件，加“预览 → 确认合并恢复”的流程。复用已有 Node 运行时，不安装新依赖，不新增浏览器权限。

直接复制两个 JSON 文件容易得到不一致的时间点，也缺少恢复冲突检查；数据库迁移增加不必要改动。本轮保持现有数据格式，新增受控备份和事务恢复模块。

## 用户流程

### 创建备份

资料库增加“备份与恢复”区域，明确显示“包含摘录与整理信息，不包含实际下载文件”。点击“创建本地备份”后显示保存状态；完成后展示备份时间、摘录数量、标签/集合数量、文件大小和“打开备份目录”。

默认保存到当前资料目录的“备份”子目录，使用时间及随机编号生成文件名，不覆盖旧备份、不自动删除备份。用户可通过文件管理器复制到另一磁盘；界面提示同一磁盘上的备份不能抵御磁盘损坏。

### 预览恢复

点击“选择备份文件”，通过本机文件选择框选择。先检查格式版本、完整性、记录编号唯一性、字段类型、长度和整理信息引用，生成有效期 15 分钟的恢复预览。只返回预览编号和统计，不把完整原文发送给浏览器。

预览显示：备份创建时间、当前资料目录、将新增的摘录、已存在且相同的摘录、同编号不同内容的冲突、将新增的标签和集合，以及缺失下载文件的说明。冲突最多列出前 50 项摘要，同时给出完整数量；摘要不展示完整敏感原文。

选择文件或预览不会写入现有资料。取消、关闭窗口或预览过期均不触发恢复。

### 确认恢复

只有用户点击“确认合并恢复”后执行：

1. 重新核对备份校验值、预览时的当前数据指纹与目标目录；任一变化都要求重新预览。
2. 自动创建恢复前备份，成功后才允许修改现有数据。
3. 以事务方式写入合并结果，全部完成后才显示成功。
4. 显示新增、跳过、冲突保留数量，以及恢复前备份路径；刷新资料库。

本轮只提供安全的合并恢复，不提供“一键清空并覆盖”。重复恢复相同备份不得产生重复摘录。

## 合并规则

摘录按现有 UUID 合并：不存在则新增；编号与全部记录字段相同则跳过；编号相同但字段不同则保留当前记录并计为冲突。不同编号即使正文相同也保留，这是现有“每次保存独立记录”的语义。

标签、集合按精确名称合并，保留大小写及用户输入，不擅自改名。当前已有资料的分类关联取并集，不移除当前分类；作者等单值整理字段在冲突时保留当前值。备份中的合法未知摘录字段原样保留，不能因恢复降级丢失。

下载快照只恢复元信息与原路径引用，不创建下载任务、不自动联网、不移动文件。已存在同 ID 快照以当前为准；原路径不存在时资料库显示文件缺失。必须保留完整快照来源标识，不把另一目录的同编号条目静默当成同一资料；跨设备路径映射留待迁移功能。

## 备份格式与校验

采用专用扩展名 .jingcai-backup.json。封装包含 format、schemaVersion、createdAt、应用版本、数据段及其 SHA-256。校验用于检测损坏，不是来源签名；任何备份文件都当作不可信输入验证。

数据段保存摘录数组、整理索引及两份原始文件的存在状态。每条摘录仍要求有效 UUID、time、type、content；来源字段只允许 HTTP/HTTPS，标签/集合采用现有长度限制；拒绝重复 ID、非支持版本、格式损坏、危险属性名、路径越界及符号链接逃逸。下载路径只是数据引用，恢复过程不读写引用文件。

首次实现单个备份上限 100 MB、摘录上限 100000 条；超限明确提示且不写入。读取前先检查文件大小，生成时检查最终编码长度。磁盘空间不足、权限失败和目录失效均显示具体原因，不把未完成文件当作可用备份。

## 并发与故障恢复

所有摘录和资料库写入须遵守同一锁顺序：先取目录级 journal Mutex，再取 library named pipe；禁止反向嵌套。正常查询、保存、删除、分类编辑、下载完成快照与备份恢复都必须检测未完成恢复事务。

恢复使用目录内专用事务文件，保存恢复前原始字节、目标指纹、阶段和恢复编号；对每份文件先写临时文件，再原子替换。若过程中失败则还原两份原始文件；若进程被终止，下次访问先完成回滚再允许正常读写。事务文件必须原子更新，不能把不完整事务当成功。

恢复前文件不存在时，回滚恢复“不存在”的状态。事务和预览路径均由本地程序生成，浏览器只能提交预览 ID，不能指定任意源或目标路径。恢复期间阻止新的保存和整理写入，待保存队列继续保留原编号。

## 接口与模块边界

- 新增 native/library-backup.cjs：备份格式验证、合并计算、预览、备份和恢复事务。
- native/host.ps1 与 native/library.ps1：统一锁和原生文件选择器入口，保持 PS 5.1 兼容。
- native/library.cjs：进入资料库操作前检查事务状态，复用既有摘要与文件状态计算。
- extension/background.js：仅允许精确的 library.html 页面调用备份接口；检查新宿主能力 library-backup-v1。
- extension/library-backup.js：独立管理备份/恢复 UI、请求序号、预览过期、确认防重入及失败提示。
- 接口按职责为 backup-create、backup-list、backup-open、restore-choose、restore-preview、restore-apply；最终动作名称由实施计划统一列出。取消文件选择返回 cancelled，不报失败。

更新安装、修复、便携与公开包白名单，新增模块必须随安装复制。目标版本 1.26.0，扩展和本地程序一起更新。未完成验收前不更改已发布能力描述。

## 验收

1. 创建含中文、长正文、来源、作者、标签和集合的备份；修改现有资料后预览恢复，冲突统计准确。
2. 恢复已删除摘录，保留当前新增摘录；连续恢复两次不重复；同编号冲突不覆盖当前内容。
3. 备份损坏、未知版本、重复 ID、异常路径及超过上限均拒绝且原数据不变。
4. 在两个文件替换之间模拟异常和杀进程，重开后两份数据一致；恢复前备份可再次验证。
5. 并发保存、分类编辑及完成任务快照不会丢失；预览后资料变化要求重新预览。
6. 取消选择、双击确认、断连、旧宿主、320/390/600/1440 像素界面与键盘操作正常。
7. 运行原有 P0/P1 和下载回归；更新功能介绍、使用说明及隐私说明；验证临时目录 SkipRegistration 安装和升级保留数据，不修改真实 Chrome 注册，不自动发布 GitHub。

## 自检

范围聚焦资料数据备份，未混入新电脑自动注册、下载文件迁移或云同步。合并规则、冲突保留、校验、预览失效、双文件事务与崩溃恢复均有明确验收。备份会包含原文和原路径，界面必须说明其可能包含私人资料，不应公开上传。
