# P0：首次可用、统一收集、失败恢复

日期：2026-10-08
状态：用户已于 2026-10-08 确认设计；进入实施计划，尚未实现

## 目标与范围

用户已选择产品建议中的前三个 P0 项：安装引导与连接自检、统一收集入口、可操作的失败提示。本次目标是让个人用户完成“装好 → 收集 → 保存成功或知道如何恢复”。保留一个 Chrome 扩展与一个根目录入口“开始使用.cmd”。不加入云同步、AI 整理、团队协作或新下载引擎。

成功标准：用户能区分安装完成与浏览器连接成功；无须先选内容类型即可载入文字或网址；常见失败有准确说明及可执行下一步；重试不会重复创建已提交任务。

## 方案选择

采用渐进整合：在现有 app 外壳增加“收集”入口，复用摘录队列、视频解析、文件识别与模型选择流程；管理中心增加诊断；前后端建立共享错误契约。

替代方案一是仅修改提示与导航标题，成本较低，但不能完成文字与链接统一收集，也无法验证实际连接。替代方案二是重写全部侧栏页面，能统一布局，但回归面大、推迟交付。本轮选择渐进整合。

## 1. 安装引导与连接自检

管理中心展示“加载扩展 → 安装本地程序 → 在扩展中验证连接”的步骤。安装前检查 Windows x64、扩展 ID 格式和目标目录；引擎下载沿用明确 URL 与 SHA-256 锁定策略。

扩展提供集中连接面板：显示自己的 ID、复制按钮、重新检测与分步安装说明。优先复用已有安装的 ID；初次安装保留一次 ID 粘贴。本轮不扫描浏览器配置目录、不修改 Chrome 配置、不通过启动未知本机命令实现自动绑定。

管理中心诊断当前有效原生通信注册、manifest 指向、允许的扩展 ID、宿主文件、依赖和保存目录可写性。分别显示通过、失败、待验证。依赖存在不代表版本正确：校验安装清单/固定哈希结果，必要时显式触发完整检查。目录写入探测只创建并删除本次随机临时文件。

浏览器中的真实 Native Messaging 响应才允许显示“Chrome 已连接”。管理中心只确认本机安装条件；它不能把文件存在当作连接成功。扩展通过独立只读诊断动作检查宿主、版本能力、引擎与目录，不复用会自动刷新待保存队列的 status 逻辑。

本地程序不可用时，扩展展示如何打开“开始使用.cmd”；可用时可通过受限动作打开已验证安装来源的管理入口。若无法安全确定入口，继续提供明确操作指引，不接受网页传入的任意路径或命令。

## 2. 统一收集入口

新增“收集”页作为首次打开默认页，原有内容摘录、视频/图集、文件下载继续保留，已有用户的当前页偏好保留。输入框接受用户粘贴的文字或一个 HTTP/HTTPS 网址，提供“使用当前网页”。不后台读取剪贴板。

文字：展示原文预览，默认“内容”，可切换评论、评阅、提示词；提示词标题沿用本地规则并可修改。用户确认后经 background 的统一入队函数写入待保存队列，沿用记录编号和失败恢复机制。

网址：提供“保存网址”与“下载内容”两个明确意图，不把所有网址都当下载命令。下载意图复用现有识别：支持的视频/图集进入对应选择页，HF 进入文件清单，普通文件进入预览；普通网页可保存网址或尝试解析，不承诺整页正文抓取。

多个网址或文字混合网址不猜测自动下载。保留文字保存选项；纯多链接输入提示进入现有批量流程。无效协议不执行导航或下载。

右键“收集所选内容 / 收集链接”进入同一预览，保留旧的直接保存菜单作为快捷操作。来源标题与地址仅用于界面与本次草稿上下文，持久化字段变更需保持旧 JSON 读取兼容。

草稿按窗口隔离，通过 session storage 传递；重开面板恢复当前会话草稿。异步结果按草稿编号/版本隔离，旧识别返回不得覆盖新输入。切页与双击不重复提交；超时且结果不明时先核对原记录/任务，而非创建新 ID。

## 3. 可操作的失败提示

错误响应保留旧的 error 字段，增加稳定 code、retryable 与安全 details。前端根据 code 和当前操作生成恢复按钮。不得由引擎日志指定执行命令。旧宿主与历史任务通过保守兼容分类处理，无法明确分类时显示“未能完成”及原始详情，不将所有 403 都判定为登录过期。

| 情况 | 提示及动作 |
| --- | --- |
| 本地未连接 / 原生注册错误 | 打开安装说明、复制扩展 ID、重新检测 |
| 宿主缺少能力 / 引擎缺失 | 引导管理中心更新修复，完成后重新检测 |
| 明确要求登录 | 打开对应原网页；仅已有支持平台提供用户主动获取登录态入口 |
| 明确链接过期 | 重新获取内容；需要新下载时重新确认，不盲目合并旧片段 |
| 磁盘空间不足 | 打开原目录、提示清理后继续；更换目录只应用后续或明确新建的任务 |
| 保存目录无权限 / 已失效 | 重新选择目录；摘录队列保留，修复后按原 ID 重试 |
| 临时网络错误 | 原任务继续或重新识别；保留现有兼容重试限制 |
| 证书 / 完整性校验失败 | 显示明确原因，处理后重新尝试，不关闭验证 |
| 不支持 / DRM | 说明边界、打开来源，不提供虚假的“修复” |
| 提交超时、状态未知 | 查看任务或检查待保存队列，避免重复提交 |

统一错误卡包含：发生了什么、当前内容是否保留、一个主要恢复动作、折叠详情。只显示当前上下文允许且可执行的按钮；不可续传任务不出现“继续”。批量错误按项保留，成功项不再次执行。

默认详情与可复制诊断隐藏 Cookie、授权头、URL 查询参数及不必要的本机路径。不得把完整敏感下载 URL 放入通知或默认错误卡。

## 模块与数据边界

- app.html/app.js/app.css：收集页导航、连接摘要、现有窗口偏好兼容。
- 新增独立收集模块：纯输入分类、草稿生命周期、预览与提交；复用 video-url.js，避免复制站点规则。
- background.js：统一摘录入队、可信扩展页面请求校验、草稿分发、结构化错误透传。
- 新增错误呈现模块：分类兼容层、脱敏、按上下文恢复动作；接入 popup、download、video 和任务卡。
- native/host.ps1 与相关工作进程：只读诊断、可确定错误码、旧响应字段兼容；异步失败写回原任务。
- tools/start-center.ps1 与独立诊断脚本：分步引导、异步自检、修复后重新检测，兼容标准与便携注册。
- 安装/便携/打包白名单：包含新模块，不包含运行时诊断与用户数据。

后台动作仅允许同一扩展的明确页面调用；网页内容脚本不能发起原生管理操作。渲染用户输入使用 textContent，不拼接 HTML。

## 实施顺序与验收

1. 安装诊断与连接面板：测试未安装、损坏注册、ID 不匹配、引擎缺失、目录不可写、旧宿主、便携模式和重新检测。失败不能导致整个面板不可用，UI 检查期间保持响应。
2. 统一收集：测试文字、提示词、单网址、www 网址、多网址、HF、视频、普通文件、网页、无效协议；测试双击、快速切换输入、多窗口隔离、超时和失败后原编号重试。
3. 错误恢复：覆盖分类矩阵、旧错误兼容、信息脱敏、按钮实际效果；验证暂停/继续、源版本变化与磁盘异常仍遵守既有恢复规则。
4. 回归与呈现：运行相关现有测试及核心测试；检查 320/390 像素侧栏、键盘导航、焦点与 loading 状态；管理中心以自测模式验证，不修改实际用户注册。
5. 更新 README、showcase/features.json、使用说明.md 和必要版本号，执行 native/bin/node.exe tools/build-showcase.cjs。公开发布另按 package.ps1 -PublicRelease 并在临时目录 SkipRegistration 验证；本请求不直接发布 GitHub Release。

## 自检结果

本设计区分安装条件与真实连接，保留用户确认下载和旧数据兼容；错误恢复不扩张 Cookie 权限、不自动迁移下载片段、不制造下载能力承诺。没有未决的必需技术选项；实现中若发现跨进程协议需要扩大改动，应先更新本设计。
