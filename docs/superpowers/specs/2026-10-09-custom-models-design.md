# 统一自定义模型管理

日期：2026-10-09

状态：界面与功能方案已获用户确认；本文待审阅，尚未进入实施阶段。

## 目标和已确认范围

将当前 OpenAI、DeepSeek 固定配置位及公司配置选择框替换为统一自定义模型列表。所有模型都能编辑、测试、删除、设为默认，不在界面上区分个人与公司。支持多个同供应商配置，来源只作为导入去重和配置维护的内部记录。

首次读取本机 WorkBuddy 的 SMEC 模型配置，保留 CC-Switch 导入入口。用户明确授权配置完成后进行实际连通测试；测试只发送简短固定消息，不发送资料库内容。

本次智能功能范围是已有文字摘要。模型名字包含 Vision 不代表本次增加图片理解、OCR 或音视频转录。跨电脑资料迁移仍不实施。

## 已核对的事实

- 当前程序仅存储两个固定手动配置，摘要使用浏览器端最近选择，没有完整的默认模型管理。
- 本机 WorkBuddy models.json 含 13 个 SMEC 配置，包含接口、密钥和显示名称。未在输出或文档中记录密钥。
- CC-Switch 的 yqn Claude 配置有两个不同模型：glm-5.2、qwen3.7-max。
- 2026-10-09 只读请求 SMEC 的 /v1/models 返回 HTTP 200。WorkBuddy 的 13 个模型均能在网关返回的模型 ID 中找到对应项。
- WorkBuddy 本地 ID 如 custom:smec-glm-5.2 是本地别名，网关实际 ID 为 glm-5.2。不能把本地别名直接作为请求模型。
- 获取模型列表成功不等于每个模型完成生成测试；最终验收须分别报告。

## 界面和操作

入口保留在资料库，标题改为“模型管理”。顶部显示当前默认模型，提供“添加模型”和“导入模型”。列表每行显示名称、模型 ID、测试状态及默认标记，提供编辑、测试、设为默认、删除。小屏幕按行换行展示操作，弹窗在窄屏下使用可滚动全宽布局。

添加和编辑共用弹窗：显示名称、供应商预设、接口地址、协议、模型 ID、SK。供应商预设包括 OpenAI、DeepSeek 和自定义；选择预设自动填写当前支持的接口、协议和模型，用户可以修改。协议明确区分 OpenAI Responses、OpenAI 兼容 Chat Completions 和 Anthropic Messages。

底部有“测试连接”“保存”“取消”。允许保存前测试草稿，不要求先保存才能测试。已有密钥只显示“已保存”，不向浏览器返回原文；输入留空保留原密钥。修改接口后不能把旧密钥自动发送到新地址，需要用户重新填写密钥。修改影响请求的字段后清除旧测试结果；测试失败不丢失表单。

保存不隐式改变默认模型。默认模型在列表中明确标识，摘要入口显示“使用模型：名称”，无需再次打开设置寻找使用入口。没有默认模型时，生成按钮提示到模型管理设置；已删除或失效的默认模型不自动切换到其他服务。

所有模型均允许编辑和删除，包括导入模型。删除要求一次行内确认；删除当前默认模型会清除默认选择并提示重新设置。弹窗支持键盘操作、关闭后焦点返回原操作按钮，SK 不进入日志、页面提示或截图测试输出。

## 导入规则

首次成功连接模型管理时，在本机程序内读取固定用户路径的 WorkBuddy models.json，只导入 SMEC 网关的配置。文件不存在或无法解析时显示可操作提示，并提供 CC-Switch 导入选项，不阻止手动添加。自动导入不调用生成接口。

导入面板允许从 WorkBuddy 或 CC-Switch 刷新配置。CC-Switch 读取仍为只读，不修改源数据库；WorkBuddy 文件也保持不变。

统一存储导入配置的加密副本，使其与手动配置具有完全相同的编辑和使用行为。来源记录包含来源类型、来源条目标识和上次导入指纹，不含明文密钥。运行摘要时使用插件已保存的配置，不依赖源应用正在运行。

WorkBuddy 模型 ID 先采用网关列表中的精确匹配；对于已核实的 SMEC custom:smec- 别名，去前缀后的 ID 必须匹配网关列表才能标为已解析。列表不可访问时保留候选 ID 并标为待验证，不声称已连通；用户可编辑模型 ID 后测试。只允许向该配置自己的接口查询模型清单，不向其他地址转发凭据。

重复导入首先根据来源条目标识去重，再用规范化接口、协议、模型 ID 和凭据指纹判断是否为同一配置，避免错误合并不同账号。重复打开页面不重复添加。首次自动导入完成后不在每次打开时覆盖配置。

显式刷新时：新增条目可导入；本地未编辑条目可更新；本地编辑过的条目保留并提示差异，只有用户选择覆盖才更新。已删除条目记录忽略标记，自动导入不复活，显式导入允许用户恢复。来源删除模型不删除插件副本。任何配置更新都不改变用户设置的默认模型。

## 数据与接口

本机 ai-settings.json 升级为 schemaVersion 2，保存稳定 ID 的模型集合、defaultProfileId、来源信息和导入状态。每个模型包含显示名称、协议、请求模型 ID、接口地址、认证方式、DPAPI 加密密钥、配置 revision 和与 revision 绑定的最近测试状态。

旧 schemaVersion 1 的 OpenAI/DeepSeek 配置升级时保留已有 DPAPI 密文。升级使用现有互斥锁和原子写入，不覆盖损坏文件；失败时保留旧文件并报告错误。旧浏览器 aiSelection 能映射到有效配置时保留选择为默认；无法映射时要求用户选择，不猜测替代项。这是内部配置升级，不是跨电脑资料迁移功能。

设置查询只返回白名单元数据和 hasKey；密钥只在保存时从弹窗传至本机，在本机加密存储。测试已保存配置按 ID 解析；测试草稿由本机验证字段后执行，不保存草稿密钥。支持列表、增改、删除、默认设置、导入预览/应用、草稿测试和已保存模型测试；后台保持仅信任本扩展资料库顶层页面的校验。

协议与供应商预设分离。通用 Chat Completions 不携带 DeepSeek 专有参数；旧 OpenAI Responses、DeepSeek 和 Anthropic 的已支持行为继续回归验证。请求有超时、响应大小限制和可理解的错误分类；不自动重试生成请求。

文字摘要按默认模型创建准备任务，任务绑定模型 ID、配置 revision、资料版本；确认前显示模型和目标接口域名。默认或配置变更使旧准备任务失效，已经运行的请求继续绑定原配置。已有请求去重、未知状态恢复和原文不变的约束保持。

## 验收和发布

1. 单元与集成测试覆盖配置升级、加密保存、草稿测试、默认模型、导入去重/本地编辑/删除抑制，以及旧摘要任务的兼容行为。
2. 用脱敏夹具验证 WorkBuddy 13 项导入、别名映射和 CC-Switch 读取，不在测试产物中留下真实密钥。
3. 界面验证添加、编辑、保存前测试、删除、设默认和摘要入口，在 320、390、600、1440 像素宽度检查布局及键盘焦点。
4. 根据本次用户授权，完成配置后对导入的 13 个模型分别发起一次固定简短生成请求，限制并发与输出，记录模型、HTTP/错误分类、是否产生有效文本和耗时。没有密钥的手动预设不测试，并明确标为未配置。禁止把模型列表 HTTP 200 当成生成成功。
5. 逐个汇报成功、失败和未测试模型；不自动切换协议、换密钥或无限重试。真实测试不自动指定用户默认模型。
6. 更新 showcase/features.json、使用说明.md、隐私说明和相关入口文案；构建生成的功能介绍，运行相关回归检查；发布本地 ZIP 时使用项目规定的打包脚本和隔离安装验证。
